How outgoing mail is sent

Send both keeps your words readable to everyone and adds an encrypted copy. PGP only sends just the encrypted block — people without PGP cannot read it.

About draft autosave

Gmail and Outlook can autosave what you type before NewPGP encrypts it. That saved copy lives with your webmail provider. NewPGP itself never writes message text to browser storage, but we cannot control the webmail site.

For highly sensitive mail, use the built-in NewPGP client instead of a webmail compose window.

The NewPGP helper

Real encryption happens in a small helper on your computer, not in the browser. Your private keys stay there; this extension only sends text to be encrypted or decrypted. You register the helper once, using the installers in the NewPGP source tree:

  1. Build or download the newpgp CLI, then run native-host/install.ps1 on Windows (for example .\install.ps1 -ChromeExtensionId <your-id> -Executable "C:\path\to\newpgp.exe") or native-host/install.sh <chrome-id> [firefox-id] [path-to-newpgp] on macOS/Linux.
  2. The installer registers com.newpgp.bridge and writes the native messaging manifest (com.newpgp.bridge.json, e.g. under %LOCALAPPDATA%\NewPGP on Windows).
  3. Use your real extension ID, exactly as the browser shows it. Firefox uses newpgp@newpgp.local; Chrome and Edge use their own 32-letter ID. An ID mismatch makes the browser refuse to launch the helper.
  4. Restart the browser and reload this extension.

There is no background service to keep running. The browser starts the helper automatically whenever the extension needs it. If the popup says “Helper not found”, re-run the installer and reload the extension.

How it works
  1. The content script reads your compose draft in memory only.
  2. The background worker asks the helper to encrypt it for your recipients.
  3. Your original text is kept and the armored block is appended (or replaces it in PGP-only mode).
  4. Incoming blocks get a decrypt button and a signature status.
