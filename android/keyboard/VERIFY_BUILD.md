# Build verification for `android/keyboard` (v0.1.4)

This records the exact commands used by `.github/workflows/android-apk.yml` so the
result can be reproduced locally. There is no committed Gradle wrapper JAR, so the
workflow always uses the `gradle` on PATH after pinning it to 8.13.

v0.1.4 adds two generated inputs that must exist **before** Gradle runs:

1. **Native crypto bridge** — `app/src/main/jniLibs/<abi>/libnewpgp_mobile.so`,
   built from the `newpgp-mobile` Rust crate with `cargo ndk` for three ABIs.
   Android Gradle Plugin picks up `app/src/main/jniLibs` automatically; no extra
   `sourceSets` configuration is required.
2. **Bundled local AI model** — one or more `*.tflite` files under
   `app/src/main/assets/models/`, generated by `tools/convert_grammar_model.py`
   from the public Hugging Face model `pszemraj/grammar-synthesis-small`.

`android-actions/setup-android@v3` is deliberately **not** used: it runs
`sdkmanager tools`, a package that no longer exists. The GitHub-hosted runner
already provides the SDK and NDK.

## CI commands (debug job)

Runs on `ubuntu-latest` with job-level
`ANDROID_HOME=ANDROID_SDK_ROOT=/usr/local/lib/android/sdk`.

### 1. SDK

```bash
set -euo pipefail
SDKMGR=""
if command -v sdkmanager >/dev/null 2>&1; then
  SDKMGR="$(command -v sdkmanager)"
elif [ -x "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" ]; then
  SDKMGR="$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager"
else
  SDKMGR="$(find "$ANDROID_HOME/cmdline-tools" -mindepth 3 -maxdepth 3 \
    -type f -name sdkmanager 2>/dev/null | sort -V | tail -n 1 || true)"
fi
if [ -z "$SDKMGR" ] || [ ! -x "$SDKMGR" ]; then
  echo "sdkmanager was not found under $ANDROID_HOME/cmdline-tools" >&2
  exit 1
fi
yes | "$SDKMGR" --licenses > /dev/null 2>&1 || true
"$SDKMGR" "platforms;android-36" "build-tools;36.0.0"
```

### 2. Generate the bundled AI model

Python 3.11 is installed with `actions/setup-python@v5`. Dependencies are pinned.
The workflow prefers `tools/convert_grammar-requirements.txt` when the converter
ships one; otherwise it uses the pinned inline set (`torch`, `numpy`,
`transformers`, `huggingface-hub`, `safetensors`, `sentencepiece`,
`ai-edge-litert`, `litert-torch`, `litert-quantizer`). The pins are chosen to be
mutually compatible with `litert-torch` 0.10.0 (`torch<2.15`,
`ai-edge-litert<2.4`) and `litert-quantizer` 0.11.0 (`ai-edge-litert==2.3.0`).
The model is public, so no `HF_TOKEN` is needed.

```bash
set -euo pipefail
SCRIPT="tools/convert_grammar_model.py"
OUT="android/keyboard/app/src/main/assets/models"
[ -f "$SCRIPT" ] || { echo "Missing $SCRIPT" >&2; exit 1; }

python -m pip install --upgrade pip
# Either: python -m pip install -r tools/convert_grammar-requirements.txt
# Or the pinned fallback used by CI:
python -m pip install --index-url https://download.pytorch.org/whl/cpu "torch==2.14.0" \
  || python -m pip install "torch==2.14.0"
python -m pip install \
  "numpy==1.26.4" \
  "transformers==4.48.3" \
  "huggingface-hub==0.34.4" \
  "safetensors==0.5.2" \
  "sentencepiece==0.2.0" \
  "ai-edge-litert==2.3.0" \
  "litert-torch==0.10.0" \
  "litert-quantizer==0.11.0"

mkdir -p "$OUT"
python "$SCRIPT"
count="$(find "$OUT" -type f -name '*.tflite' -size +0c | wc -l)"
[ "$count" -gt 0 ] || { echo "No non-empty .tflite in $OUT" >&2; exit 1; }
find "$OUT" -type f -name '*.tflite' -printf '%p (%s bytes)\n'
```

The converter writes an encoder and a decoder `.tflite` plus `tokenizer_vocab.tsv`,
`tokenizer_metadata.txt` and `manifest.json` into that directory (defaults:
`grammar_small_q8.tflite` and `grammar_small_q8_decoder.tflite`). CI does not pass
`--strict`: the default int8 recipe produces roughly 75-85 MB of combined models,
which is outside the script's advisory 30-60 MB window. Use
`--recipe dynamic_wi4_afp32 --encoder-name grammar_small_q4.tflite` if the smaller
size is required.

The workflow fails with an `::error::` annotation if the script is missing, exits
non-zero, or produces no non-empty `.tflite` file.

### 3. Build the Rust crypto bridge

`cargo-ndk` needs the three Rust Android targets and an NDK. On `ubuntu-latest`
the NDK is preinstalled (e.g. `$ANDROID_HOME/ndk/27.3.13750724` and a newer
`$ANDROID_NDK_LATEST_HOME`); the workflow discovers the newest directory and
exports `ANDROID_NDK_HOME` for later steps.

```bash
set -euo pipefail
rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk --locked

NDK="$(find "$ANDROID_HOME/ndk" -mindepth 1 -maxdepth 1 -type d | sort -V | tail -n 1)"
[ -d "$NDK" ] || { echo "No Android NDK found" >&2; exit 1; }
export ANDROID_NDK_HOME="$NDK"
export ANDROID_NDK_ROOT="$NDK"

LIBDIR="android/keyboard/app/src/main/jniLibs"
# newpgp-mobile is currently its own workspace root, so point cargo at its
# manifest explicitly; -p keeps the built package explicit.
cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 \
  -o "$LIBDIR" build --release \
  --manifest-path crates/newpgp-mobile/Cargo.toml -p newpgp-mobile

for abi in arm64-v8a armeabi-v7a x86_64; do
  found=""
  for name in libnewpgp_mobile.so libnewpgp_jni.so; do
    [ -s "$LIBDIR/$abi/$name" ] && { found="$name"; break; }
  done
  [ -n "$found" ] || { echo "No native library for $abi in $LIBDIR/$abi" >&2; exit 1; }
done
```

The ABI flags map as follows:

| `cargo ndk -t` | Rust target triple             |
| -------------- | ------------------------------ |
| `arm64-v8a`    | `aarch64-linux-android`        |
| `armeabi-v7a`  | `armv7-linux-androideabi`      |
| `x86_64`       | `x86_64-linux-android`         |

Note on the library name: `crates/newpgp-mobile` currently declares
`crate-type = ["rlib", "staticlib"]`, so `cargo ndk` alone does not emit a
`libnewpgp_mobile.so` cdylib. The Android CMake project links that static archive
into `libnewpgp_jni.so`. CI therefore accepts either `libnewpgp_mobile.so` or
`libnewpgp_jni.so` for each ABI. If the crate is later switched to a `cdylib`, the
`libnewpgp_mobile.so` name applies directly. Coordinate any change to the Kotlin
`System.loadLibrary` name with this check.

### 4. Gradle build and both unit-test suites

`gradle/actions/setup-gradle@v4` puts Gradle 8.13 on PATH.

```bash
cd android/keyboard
# Debug keyboard APK + its JVM unit tests:
gradle assembleDebug :app:testDebugUnitTest

# Companion app is a separate Gradle root; run its unit tests too:
cd ../../android/app
gradle assembleDebug :app:testDebugUnitTest
```

If a wrapper JAR is committed later, prefer `./gradlew` in place of `gradle`.
Artifacts uploaded by CI:

| Artifact                    | Path                                                        | Missing-files policy |
| --------------------------- | ----------------------------------------------------------- | -------------------- |
| `newpgp-keyboard-debug`     | `android/keyboard/app/build/outputs/apk/debug/*.apk`         | `error`              |
| `newpgp-android-app-debug`  | `android/app/app/build/outputs/apk/debug/*.apk`             | `error`              |
| `newpgp-keyboard-tests`     | `android/keyboard/app/build/test-results/**/*.xml`          | `warn`               |
| `newpgp-android-app-tests`  | `android/app/app/build/test-results/**/*.xml`               | `warn`               |

## CI commands (release job)

Eligible only on `refs/tags/v*` **and** when all four secrets are set:
`NEWPGP_KEYSTORE_BASE64`, `NEWPGP_KEYSTORE_PASSWORD`, `NEWPGP_KEY_ALIAS`,
`NEWPGP_KEY_PASSWORD`. If any is missing, every real step is skipped and the job
finishes successfully with a notice; no artifact is uploaded and no release is
published. Secrets are turned into a job-level env var (`SIGNING_READY`) because
GitHub does not allow `secrets.*` in an `if:` expression. The release job repeats
the model-conversion and `cargo ndk` steps so the signed APK contains the same
native library and model as the debug APK.

```bash
cd android/keyboard
echo "$NEWPGP_KEYSTORE_BASE64" | base64 --decode > app/newpgp-release.jks
ORG_GRADLE_PROJECT_NEWPGP_UPLOAD_STORE_FILE=app/newpgp-release.jks \
ORG_GRADLE_PROJECT_NEWPGP_UPLOAD_STORE_PASSWORD="$NEWPGP_KEYSTORE_PASSWORD" \
ORG_GRADLE_PROJECT_NEWPGP_UPLOAD_KEY_ALIAS="$NEWPGP_KEY_ALIAS" \
ORG_GRADLE_PROJECT_NEWPGP_UPLOAD_KEY_PASSWORD="$NEWPGP_KEY_PASSWORD" \
  gradle assembleRelease
```

`app/build.gradle.kts` reads those properties only when all four are defined; a
plain `gradle assembleDebug` (or `assembleRelease` without them) configures and
builds without any keystore. A debug-signed APK is fine for local install but is
not accepted by Google Play or F-Droid: Play requires an upload key plus Play
App Signing (signing key valid past 22 October 2033), while F-Droid builds from
source and signs with its own key, so keep the generation steps deterministic
and self-contained. Never commit the keystore or passwords.

## Run locally

Prerequisites: JDK 17, Android SDK platform 36 + build-tools 36.0.0, Python 3.11,
Rust with `rustup`, and `cargo-ndk`.

Linux / macOS:

```bash
export ANDROID_HOME=/path/to/Android/Sdk
export ANDROID_SDK_ROOT="$ANDROID_HOME"
"$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" "platforms;android-36" "build-tools;36.0.0"

python3 -m venv .venv-model
source .venv-model/bin/activate
# Install the pinned converter requirements (see the CI step above for exact pins),
# then generate the model into app/src/main/assets/models:
python tools/convert_grammar_model.py

rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk --locked
export ANDROID_NDK_HOME="$(find "$ANDROID_HOME/ndk" -mindepth 1 -maxdepth 1 -type d | sort -V | tail -n 1)"
cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 \
  -o android/keyboard/app/src/main/jniLibs build --release \
  --manifest-path crates/newpgp-mobile/Cargo.toml -p newpgp-mobile

cd android/keyboard
gradle --no-daemon assembleDebug :app:testDebugUnitTest
```

Windows PowerShell (cargo-ndk supports Windows hosts):

```powershell
$env:ANDROID_HOME = "C:\Users\<you>\AppData\Local\Android\Sdk"
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.cmd" "platforms;android-36" "build-tools;36.0.0"

py -3.11 -m venv .venv-model
.\.venv-model\Scripts\Activate.ps1
python tools/convert_grammar_model.py

rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
cargo install cargo-ndk --locked
$env:ANDROID_NDK_HOME = (Get-ChildItem "$env:ANDROID_HOME\ndk" -Directory | Sort-Object Name | Select-Object -Last 1).FullName
cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -o android/keyboard/app/src/main/jniLibs build --release --manifest-path crates/newpgp-mobile/Cargo.toml -p newpgp-mobile

cd android/keyboard
gradle assembleDebug :app:testDebugUnitTest
```

Verified configuration: JDK 17, Gradle 8.13, AGP 8.11.1, Kotlin 2.2.0,
`compileSdk = 36`, `minSdk = 24`, `buildToolsVersion = "36.0.0"`.
`cargo-ndk` requires Rust >= 1.86; this workspace pins `rust-version = 1.88`.

## Verify the APK really contains the native library and the model

From the repository root (Linux/macOS):

```bash
APK=android/keyboard/app/build/outputs/apk/debug/app-debug.apk
for abi in arm64-v8a armeabi-v7a x86_64; do
  unzip -l "$APK" | grep -Eq "lib/$abi/(libnewpgp_mobile|libnewpgp_jni)\.so" || {
    echo "Missing native bridge .so for $abi" >&2; exit 1; }
done
unzip -l "$APK" | grep -qE 'assets/models/[^ ]+\.tflite' || {
  echo "Missing bundled .tflite asset" >&2; exit 1; }
echo "OK: native bridge for 3 ABIs and .tflite model are packaged"
```

Windows PowerShell:

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$apk = [System.IO.Compression.ZipFile]::OpenRead((Resolve-Path "android/keyboard/app/build/outputs/apk/debug/app-debug.apk"))
$apk.Entries.FullName | Where-Object { $_ -match '(libnewpgp_mobile|libnewpgp_jni)\.so$|\.tflite$' }
$apk.Dispose()
```

You should see three `lib/<abi>/libnewpgp_mobile.so` (or `libnewpgp_jni.so`)
entries and at least one `assets/models/*.tflite` entry. If they are absent,
confirm the `cargo ndk` and model-conversion steps ran **before**
`gradle assembleDebug`.
